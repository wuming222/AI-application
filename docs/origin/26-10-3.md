## 3. 实测中撞到的既有缺陷（未修，记账）

现象：注册新账号或刷新页面后的头几秒里点发送，**这句话被静默丢掉** —— 没有网络请求、控制台不报错、界面不动，看起来像"输入框坏了"。

复现记录：`cdp-rag-runtime-probe.mjs` 第一轮就是这么停住的（探针当时判据是"假上游收到 2 次 `/responses`"，结果 0 次）。在页面里读 zustand 现场确认：`sessionStore.currentSessionId === null`、`chatStore.bySession` 空、侧栏 `.session-item` 为 0，而服务端日志里 `POST /api/sessions` 其实已经成功过。等 2~7 次轮询（每次 500ms + 一次 CDP 往返）之后状态才落定，此时同样的发送动作就正常了。

链路：`components/Sidebar.tsx:156` 的 `loadSessions().then(() => initFirstSession())` 是串行的 5 个 await（GET sessions → GET sessions → POST sessions → GET messages → GET workspace），冷启动 + dev 的 StrictMode 双挂载要跑两轮；而 composer 在这条链落定之前就已可用。`store/chatStore.ts:109` 的 `if (!sessionId) return` 于是成了静默丢弃点。

未修的理由与修法：属于会话初始化那一条链，不在 RAG 范围内。两个方向 —— 发送路径 await 到会话落定，或者 init 未完成时禁用 composer 并给出可见状态。要修得先定"哪一个是产品想要的形态"。
