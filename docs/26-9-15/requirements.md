## AI 消息 Markdown 换行过多

### 问题描述
对话里的 AI 消息渲染后空白行明显偏多，段落之间像被撑成了两三个空行，长回答读起来很松散。

### 排查记录
已定位到根因：消息气泡 `MessageList.tsx:168` 上有 inline `whiteSpace: 'pre-wrap'`，该属性会继承进 `.message-markdown` 子树。Markdown 已经用 `<p>` / `<li>` 等块级元素排好版，而源文本里原有的 `\n` 又被 `pre-wrap` 额外渲染了一次，于是每个段落之间叠加出多余空行。

从本地库取样的真实 assistant 消息（含 `\n\n` 分段 + 软换行）确认了这一叠加效应。

### 技术要求
- `.message-markdown` 内恢复由 Markdown 自身控制空白（`white-space: normal`），段落间距只由 CSS 的 margin 决定
- 工具执行气泡（`ToolGroupBubble`，渲染的是原始文本、不走 Markdown）必须继续保留 `pre-wrap`，不能一起改掉
- 代码块 `<pre>` 的空白行为不受影响

### 待办
- [x] 去掉 Markdown 容器继承到的 `pre-wrap`
- [x] 复核段落、列表、标题的间距是否符合预期
- [ ] 复核代码块、表格的间距 —— 当前会话数据里没有这两类样例，未实测
- [x] 确认工具气泡与用户消息的原始文本换行没有被改坏（工具气泡不带 `.message-markdown`，代码层确认）

## 空会话下点「新建会话」不应再创建一个

### 问题描述
已经处在「新对话」界面时，再点新建会话，列表上又多出一条空「新对话」；连续点会堆出好几条一模一样的空会话。

### 复现记录
浏览器实测：会话数 7（其中 3 条是空「新对话」）时连点两次新建 → 变成 9 条，顶部连着两条空的「新对话」。

根因在 `packages/web/src/store/sessionStore.ts:63`：`createSession` 无条件 `POST /api/sessions`，而 `Sidebar.tsx` 的新建按钮直接调它，全程没有"当前会话本来就是空的，复用它"这一步判断。

### 期望行为
当前会话还没产生任何内容时，点新建等于"回到干净的输入框"，不应该新增会话；只有当前会话已经有内容（发过消息 / 生成过文件）时，才真的新建一条。

### 待办
- [x] 判断放 store：新增 `createOrReuseSession`，两处新建按钮改走它，`createSession` 保持无条件新建的语义
- [x] 定义"空"：消息数为 0 且 workspace 无文件
- [x] 处理边界：无当前会话走新建；判定只看内容不看标题；流式输出时消息数已 ≥ 1，行为与现状一致
- [x] 复用时的反馈：`composerFocusTick` 把焦点送回输入框
- [x] 浏览器实测：连点新建不再堆积空会话（DOM 与后端会话数都不变），已有内容的会话仍可正常新建
