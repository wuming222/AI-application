# 分类追问清单

`SKILL.md` 里的四类缺口是自查用的；这一份是**按需求类型给的具体问句**。
使用时机：读完需求仍然判断不了"使用者与场景"或"核心动作"时，对号入座挑 **一条** 问，不要整段照抄。

## 记录 / 列表类（待办、笔记、账本、书签）

- 一条记录有几个字段？只有用户会主动填的那几个算字段，其余用默认值。
- 数据要活多久：只在本次会话里看看，还是下次打开还在？
- 有没有"改"的需求，还是只有"加"和"看"？（只加不看改的话，编辑功能可以整段省掉）
- 列表长了要不要筛？超过 20 条才会显出价值，不到就先不做。

## 展示 / 落地页类（介绍页、作品集、活动页）

- 给谁看，看完希望他做什么动作（联系、报名、下载、只是了解）？
- 内容里的文字和图片，用户现在手上有吗？没有的话用占位内容还是先问他要？
- 需要在手机上看得好吗？这一条决定布局方案，问错了返工成本最大。
- 有品牌色/字体必须用吗？没有就自己定一套并写进"待确认"。

## 工具 / 计算类（转换器、计算器、格式化工具）

- 输入从哪来：手打、粘贴、还是上传文件？（上传文件是另一个量级的工作量）
- 输出到哪：屏幕上看看、可复制、还是要能存成文件？
- 有没有边界值必须处理（空输入、超长、格式错）？用户会不会拿错的输入试你？
- 一次处理一个还是批量？批量要改交互结构，不是加个循环。

## 游戏 / 演示 / 动画类

- "可玩"的判据是什么：能操作并且有胜负/反馈，还是动起来就行？
- 操作方式是键盘、鼠标还是触屏？只写一种会直接决定能不能用起来。
- 有没有必须出现的效果？用户提到的每一个名词（"要有爆炸""要能跳"）都是验收标准。
- 结束条件是什么？没有结束条件的游戏，用户玩十秒就走了。

## 数据看板 / 图表类

- 数据是真的还是演示用的假数据？**这一条必须确认**，接真数据要问来源和权限。
- 图给谁看：自己盯趋势，还是汇报时投给别人看？后者要的是大字和结论，不是交互。
- 时间范围与更新频率。
- 数字精度要求（保留几位、要不要千分位、要不要单位）。

## 什么时候不该问

- 用户已经给了具体到文件名的要求 —— 照做。
- 答案不影响未来十分钟的产出 —— 自己定，写进"待确认"。
- 同一个问题问第二遍 —— 用户已经答过了，回去找他上一条消息，不要重复问。
